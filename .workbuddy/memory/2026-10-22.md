## 足迹模块改造方案（只出思路，未改代码）

现状摸底结论：
- `public/china.json` 是**省级** GeoJSON（35 个 feature，含台湾省/港澳），不是市级。地图渲染本身没问题，瓶颈在坐标表。
- `src/lib/cities.ts` 现有 134 条手写城市（并非只有省会，含苏州/张家界/凤凰/平遥等旅游城市），三份 Record 手工维护。
- 关键病灶是 `footprints/page.tsx:105` 的 `filter(([city]) => CITY_COORDS[city])`：未命中地名**静默丢弃**，不报错不提示。
- 匹配是 `m.location === city` 的精确字符串比对，无归一化。

## 已验证的数据源（省得下次再试）

DataV.GeoAtlas 行政区划：
- `https://geo.datav.aliyun.com/areas_v3/bound/100000_full.json` → **只有省级**（35），跟本地 china.json 同文件。
- `https://geo.datav.aliyun.com/areas_v3/bound/{省adcode}_full.json` → 该省子级，带 `properties.center`，可直接做坐标。
- 实测：遍历 34 个省级 adcode，`level === "city"` 的条目 **363 条，center 全部非空**。
- 坑：
  - `710000`（台湾省）返回 **404**，台湾各市需手工补。
  - 直辖市（110000/120000/310000/500000）子级 level 是 `district`（区），不是 city → 四个直辖市要单独手工补 1 条。
  - 海南、甘肃等省直辖县级行政区（县级市/县/自治县）也被标成 `city`，会混进来，按需过滤。
  - 子级 feature 的 `properties.parent` 只有 adcode、没有名字 → 省名要自己用 adcode 映射表补。
  - 盟/自治州/地区后缀会让名称很长，必须做归一化去后缀。

## 横屏方案的判断

- 真全屏 + `screen.orientation.lock('landscape')` 在 **iOS Safari 不可用** → 不作为主方案。
- 推荐：页面内 `fixed` 遮罩 + CSS `rotate(90deg)` 容器互换宽高，配合 `matchMedia('(orientation: landscape)')` 自适应，退出即可恢复。
- 实现时必须注意：现在只监听 `window.resize`，遮罩开合不会触发 → 需手动 `chart.resize()` 或改用 ResizeObserver。

## 已落地：城市坐标重写（未动数据库）

- `scripts/gen-cities.mjs`：遍历 34 个省级 adcode 抓 DataV 子级，筛 `level === "city"` **且 `adcode % 100 === 0`**（这条自动剔掉海南/甘肃的省直辖县级行政区，不用写省份白名单）；补 4 直辖市（取 china.json 省 center）+ 15 个台湾县市 + 港澳；合并 `scripts/legacy-cities.json`（旧 134 条快照，保证新表是旧表父集）。内置断言：无重名、无单字名、无残留后缀、坐标在中国境内、省份名必须在 china.json 的 35 个里。产物 **361 条 → `src/lib/cities.generated.ts`（44KB）**。
- `pinyin-pro` 只作为 devDependency，全拼/首字母在生成期烤进文件，运行时零依赖。
- **踩过的坑**：简称剥离不能写宽泛正则——`[\u4e00-\u9fa5]{1,4}?族` 会把「西双版纳傣族自治州」削成「西」。改用 56 个民族词干表按长度倒序拼 `(?:词干族?)+(?:自治州|自治县|自治旗)$`，再兜一层剥普通后缀。词干表见脚本里的 `ETHNIC_STEMS`。
- `src/lib/cities.ts` 重写：唯一真源 CITY_LIST + 派生的 CITY_COORDS/CITY_PROVINCE/CHINA_CITIES（旧导出名保持不变）；新增 `resolveCity`（去后缀/去空格/全角/民族自治州/别称如呼市、版纳、豫...）、`searchCities`（汉字/全拼/首字母三路，带评分排序）、`groupByCity`（按解析后的城市分组合并，「沈阳」和「沈阳市」合成一个点，解析不了的保留但 coord 为 null）。
- **结论：不必清洗历史数据。** resolveCity 在运行时就能把旧写法解析到位，一个字节都不用改就有同样效果。真要洗只是为了让卡片显示统一，收益远小于风险。
- 调用方改动：`ChinaMap.tsx` 与 `footprints/page.tsx` 改用 `groupByCity`；未定位的城市在列表里显示 ❔ + 顶部橙色提示条；`MemoryForm` 联想框改用 `searchCities`，候选项带省份，自由输入仍允许只是提示"打不了点"。
- `scripts/dry-run-locations.mjs`：只读体检（`SELECT DISTINCT location`），列出「新旧写法合并」「以前没点现在有」「仍定位不到」三类。**本地没有 DATABASE_URL（数据在 Vercel 的 Neon），需先 `vercel env pull` 才能跑**；也加了 npm scripts：`cities:gen` / `cities:dryrun`。
- 验证：tsc 干净、`npm run build` 通过、dev 页面 200。断言实测：沈阳/沈阳市/呼市/鞍山/西双版纳傣族自治州/大理白族自治州/延边朝鲜族自治州 全部命中；沈阳+沈阳市 合并为 1 组；境外与区县（沈阳市铁西区）正确落 lp 未匹配。
