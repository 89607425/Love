# 2026-11-13

## 留言板两个 bug 修复（love 项目）

- **新消息在最上面**：`db.ts` 的 `getMessages` 用 `ORDER BY created_at DESC`，前端照渲染。改成 `ASC`。该函数只有 messages API 一个调用方，改动安全。
- **聊天区滚不动**：flexbox 经典坑——`flex-1 overflow-y-auto` 的子项默认 `min-height: auto`，内容一多被撑开而不是收缩，overflow 失效，外层 `overflow-hidden` 直接裁掉内容。加 `min-h-0` 解决。
- 顺手重构：输入栏从 `fixed bottom-16`（配 `pb-44` hack）改为正常文档流的 `shrink-0` 子项，外层 `pb-16` 给底部导航留位。高度链条完整，iOS 键盘弹起行为也更稳。
- 顺带修的两个隐患：
  - GET /api/messages 有 60s 缓存，发送后 refetch 可能拿旧数据 → `fetchMessages` 加 `cache: "no-store"`，且 `handleSend` 直接把 POST 返回的新消息 append 进 state（带 id 去重）。
  - 删除按钮 `group-hover` 在触屏上永远不可见 → 改为移动端常显（弱化 opacity-40）、桌面端 hover 显示（`sm:opacity-0 sm:group-hover:opacity-100`）。
- 验证：tsc 干净、build 通过、dev 页面 200 且新布局类名在 HTML 里。本地 `/api/messages` 500 是因为没有 DATABASE_URL（数据在 Vercel Neon），与改动无关。
- 环境注意：3000 端口常被一个旧进程占用（本次 PID 88614），next dev 会自动换 3001。

## 性能优化 + 留言删除 bug（23:20 补充）

**删除不立即消失的根因**：GET /api/messages 没读 request 参数被 Next 静态化 + `public, max-age=60` 让 CDN 缓存 60s，客户端 no-store 绕不过 CDN。修复：三个 API 路由（messages/wishes/memories）改 `force-dynamic` + `private, no-store`；前端删除改乐观更新（本地先移除，失败才回滚重拉）。

**性能**：
- 4 张背景图 PNG(6.0-6.6MB) → WebP 1080px q80（261-292KB，降 23 倍），cwebp 完成，代码引用 .PNG → .webp（6 处）
- uploads 存量 2 张 5.1MB → 1600px q85（553KB，降 9 倍）；注意 MemoryForm 上传压缩本来就存在（1200px/q0.75），5MB 是早期存量
- 5 处列表 `<img>` 加 loading="lazy" decoding="async"（灯箱除外）
- 原图备份在 `originals/`（已进 .gitignore）
- 首屏体积 ~7MB → ~1MB 以内

## 留言板微信式引用回复（23:30）

- db.ts：messages 表加 `reply_to INTEGER REFERENCES messages(id) ON DELETE SET NULL`（try/catch 迁移，仿 location 列先例）；createMessage 接受 replyTo
- API POST 接收 replyTo；GET 不变（前端按 id 在已加载列表里 join 出引用内容）
- MessageBubble：长按 500ms（pointer 事件 + onContextMenu 桌面右键等效）触发操作弹层；气泡内渲染引用块（左边线 + 作者 + 内容 line-clamp-2）；原 ✕ 删除按钮移除（功能并入长按菜单）
- 页面：底部 action sheet（回复/删除/取消）+ 输入框上方微信式回复栏（可 ✕ 取消）；发送携带 replyTo；删除被回复的留言时引用块自然消失（SET NULL）
- 原留言被删后引用块消失而非显示"已删除"——数据层用 SET NULL，展示层静默处理，用户可接受
